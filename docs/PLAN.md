# Plan

## Decisions (approved)
- Targets: Debian 12+, Ubuntu 22.04+, Linux Mint 21+/LMDE 6, Fedora, Arch; x86_64 and aarch64 (aarch64 tested under QEMU).
- Bundled apps on other distros: Patina Terminal, File Bin, Settings. Cloudbreak Files and BeaconHub are IronTide OS only.
- Terminal: real PTY shell.
- Toolkit: iced + iced_layershell for shell surfaces and apps, custom wgpu pass for blur. Milestone 0 spike confirms; fallback is custom wgpu.
- First login path: GDM/LightDM/SDDM session entry first, greetd greeter later (user undecided; this was the recommendation).
- Fonts: Plus Jakarta Sans and JetBrains Mono, bundled from Google Fonts (OFL).

## Architecture
Smithay compositor plus separate layer-shell client processes (panel, dock, launcher, quick settings, session UI) so a crashed panel does not end the session. Services over zbus.

## Build constraints
Distro cargo is too old (Debian 12: 1.63, Ubuntu 22.04: 1.75). Packages build with a pinned rustup toolchain; release binaries are built in a Debian 12 container for the oldest glibc.

## Milestone 0 status
Done: repo (github.com/azevedomedia0/Patina), fonts, Lucide icons, token generator with tests, CI matrix (all eight jobs pass on GitHub; `docs/CI.md`), Rust pinned to 1.99.1 (`rust-toolchain.toml`, `packaging/RUST_VERSION`), packaging stubs, toolkit spike (docs/SPIKE.md), QEMU build VM (docs/VM.md).
Milestone 1 (nested compositor), working in the QEMU VM (`docs/spike/window-frames.png`):
- xdg-shell windows with compositor-drawn 38 px titlebars (xdg-decoration forces server-side), layer-shell, viewporter.
- Move by titlebar, resize by the bottom-right grip, maximise (control or double-click titlebar), minimise (Alt+M restores until the dock exists), close, click-to-raise and focus, hover on controls, inactive windows dimmed to 92%.
- Titlebar drawing and hit-testing live in `patina-frame` (no Wayland dependency, tested on macOS).
Also: window content is clipped to the 20 px bottom corners by a GLES shader (`clip.frag`), and each window has the design's shadow and 1 px outline (`patina-frame::shadow`, `docs/spike/window-shadow-corners.png`).
Milestone 2 (DRM/KMS) started and working in the VM (`docs/spike/drm-session.png`): libseat session via seatd, libinput keyboard and pointer (absolute and relative), udev GPU selection, GBM/EGL renderer, `DrmCompositor` per output (see Outputs below), a software cursor from the design's `cursor.png`, vblank-driven rendering, VT switching on Ctrl+Alt+F1..F12 (not yet exercised). The backend is chosen automatically: winit when run inside another session, DRM from a TTY (`PATINA_BACKEND=drm|winit` overrides). Run it with `ci/vm/guest/drm-up.sh`.
Debian packaging (`packaging/debian`, `docs/PACKAGING.md`): `patina-desktop_0.1.0_arm64.deb` builds in a pristine Debian 12 chroot, lintian is clean, installs from a bare system with all dependencies resolving, and the installed `/usr/bin/patina-session` starts a working session in the VM.
Rendering is event-driven: a frame is drawn only after a surface commit, input, window or layer change, or a title change; the idle compositor measures 0 wakeups/s and 0 ms CPU/s (it was 47/s and 13 ms/s with the old 16 ms retry timer; `ci/vm/guest/idle-wakeups.sh`). On drivers without fence support (virtio-gpu, software GL) the DRM backend waits on the render sync point before queueing a frame, as Smithay requires; skipping that showed half-drawn frames (a missing panel), which the old polling had hidden.
Cursors: the design's arrow is the default pointer; other named cursors come from the system XCursor theme (as the prototype uses stock cursors for everything but the arrow), client cursor surfaces are drawn as given, `cursor-shape` is supported, and the compositor shows the resize cursor over a window's corner grip. In the nested (winit) backend the host draws the pointer, so none of this applies there.
Panel: the clock (on the minute), battery (hidden when there is none), focused-window title (via `wlr-foreign-toplevel-management`, also needed by the dock) and the four workspace buttons (`ext-workspace-v1`; the compositor stashes windows per workspace) are live. Still not wired: the launcher button (no launcher yet), the wifi/bluetooth/brightness/volume icons (they show no state and open nothing: services and quick settings are milestone 3 and 7) and the notification bell (no notification service, so it is hidden). Super+1..4 switch workspace and Super+Shift+1..4 move the focused window there and follow it (physical number-row keys, so they work on AZERTY and similar). These shortcuts are my proposal, since the prototype has no keyboard handling for workspaces; they are non-visual and easy to change.
Glass: the desktop shows the design's `--wallpaper` (two radial glows, rendered from the CSS token in `patina-frame::wallpaper`), and the panel (`blur(16px)`) and every window (`blur(24px) saturate(1.4)`) blur what is behind them, drawn by the compositor. The frame is composed into an offscreen scene texture bottom to top (`scene.rs`); before each glass surface, the scene so far is downsampled to a quarter, blurred with a separable Gaussian and drawn back inside the surface's rounded rectangle (`blur.rs`, `gaussian.frag`, `backdrop.frag`). The scene is recomposed only when something in it changed (an element's id, commit counter, geometry or alpha), so an idle desktop stays idle (0 wakeups/s with blur on). `PATINA_NO_BLUR=1` turns it off. Verified A/B on the VM: bright content behind a titlebar is a soft haze with blur and a hard-edged block without it. Cost on the VM's software GL: a recompose takes 7-55 ms (median 33 ms) with three glass surfaces, so dragging runs at roughly 30 fps there; a real GPU should be far faster, but this is untested. Partial recompose: each glass surface keeps its own snapshot of what is below it, and the scene tracks per-element signatures, so only damaged rectangles (grown by the blur reach, 3 sigma + 48 px, and propagated up the stack) are repainted; a change to the window list or stacking, a new glass surface, or more than 60% of the screen falls back to a full recompose. On the VM's software GL a small-update run (hover, typing, a nudge) averaged 18 ms per compose at 36% of the screen, against 29 ms at 100% with `PATINA_FULL_RECOMPOSE=1`. `PATINA_VERIFY_RECOMPOSE=1` composes every frame twice (partial and full) and compares: over three runs of the varied exercise script (about 320 frames) no frame differed by more than 2/255 in a channel, and 5-6 frames per run differed by 1-2/255 somewhere in glass (counted, not failed). Those small differences reach beyond the computed blur reach and their cause is not isolated; they are invisible and the next repaint of the area removes them. Not done: HiDPI-aware blur sizes beyond scaling sigma, blur for popups and menus (none exist yet).
Outputs: every GPU with display connectors is opened and every connected display becomes an output, placed left to right (boot GPU first) at its preferred mode; each GPU renders its own outputs with its own renderer and scene. udev drives hotplug: a GPU appearing or going away, and connectors being plugged or unplugged on a GPU, add and remove outputs while the session runs. Windows live in one space spanning all outputs and are drawn on every output they overlap; maximise and the panel's reserved area use the output the window is mostly on; new windows open on the output the pointer is on; the pointer moves across outputs and cannot leave them. The compositor starts the `--per-output` command (the panel) once per output with `PATINA_OUTPUT` naming it, and stops it when the output goes; windows left with nothing on screen move to the first output. Display-only devices (no OpenGL that can render into scanout buffers: USB/DisplayLink adapters, simpledrm, QEMU's bochs-display) are drawn offscreen with their own software renderer and copied into two CPU-mapped dumb buffers (`dumb.rs`). Tested in the VM: two virtio GPUs with a display each (a window dragged across, maximised on the second, typing; verifier 240 frames, 0 mismatches; idle 0 wakeups/s); a bochs display-only adapter at boot (correct picture) and hot-plugged and hot-unplugged in a running session (output added with its panel, a window moved onto it came back to the first output on unplug, the compositor kept running). Not tested: connector hotplug on one GPU (QEMU cannot enable a virtio-gpu's second connector without a GUI), different resolutions side by side, real hardware. Not done: output configuration (arrangement, modes, scale, mirroring), remembering a window's output across unplug and replug, an output's mode changing while connected.
Milestone 2 completion (2026-10-19):
- VT switching: Ctrl+Alt+F2 to a text console and Alt+F1 back, in a running session: the session pauses and resumes, the picture comes back, and typing works afterwards (no stuck Ctrl or Alt).
- One GPU with several connectors, and connector hotplug on it: the VM's GPU with two connectors, the second plugged and unplugged while the session runs (forced through sysfs plus the kernel's change event, which is what a real plug sends). Different resolutions and scales side by side (1280x800 at 100% next to 1920x1080 at 150%).
- Windows remember their output: a window on a display that is unplugged moves to the first display and goes back to where it was when that display returns (unless it was moved by hand meanwhile). Tested by unplugging and replugging the second connector.
- A connected display whose preferred mode changes (another monitor on the same port) is set up again. A display without a preferred mode (no EDID) gets the largest mode up to 1920x1080 instead of the first listed (the VM's forced connector listed 5120x2160 first).
- After any device change (including a resume, which can blank some drivers) every display is redrawn in full.
- Touchscreens: touches go to apps as `wl_touch`; on a window frame a touch moves the window, resizes it or presses a titlebar button. The touchscreen is mapped to the built-in panel (eDP, LVDS, DSI) or else the first display. Tested with QEMU's virtio multitouch device: a tap toggles a GTK check box, a swipe on a titlebar moves the window.
- Keyboard: the layout is the system's (`/etc/default/keyboard` on Debian, Ubuntu and Mint; `localectl`'s `00-keyboard.conf` on Fedora and Arch), overridable with `XKB_DEFAULT_*`, with a fallback if the layout name is unknown; tested with a German layout. Key repeat starts after 400 ms, the prototype's default. Caps Lock, Num Lock and Scroll Lock lights follow the keyboard state (tested on the VM's USB keyboard).
- Regression: idle 0 wakeups/s, recompose verifier 103 frames, 0 mismatches.
Not testable here, so still open: suspend and resume (nothing wakes the VM's arm64 guest from suspend), and real GPUs (the VM only has software rendering). `docs/HARDWARE-TEST.md` lists what to check on a real machine.

Milestone 1 completion:
- Popups and menus (`xdg_popup`, also on layer surfaces): drawn above their window and not clipped to its corners, kept on the window's output by the positioner's rules, with the popup grab (a click outside or Escape closes a menu). Tested with `gtk3-widget-factory`: combo box list, entry context menu, a menu at the right edge flips left, click outside dismisses.
- Placement (approved rule): a new window is placed once it knows its size, centred in the free area of the output the pointer is on, stepping 32 px right and down while another window already starts there, never outside that area (a window too big for it starts at its top-left). Unit-tested in `wm.rs`.
- A panel that appears after the windows (late start, restart after a crash) moves windows out from under it: verified with a panel started 20 s late.
- HiDPI (approved rule): each output's scale comes from its pixel density (about 96 dpi per 100%, rounded to the nearest quarter between 100% and 200%; outputs reporting no or implausible size get 100%), overridden by `PATINA_SCALE` (one value, or `NAME=value,...`). Clients are told through `wp_fractional_scale_v1` and the integer buffer scale; titlebars, shadows, the wallpaper, blur and the cursors are drawn at device resolution. Verified in the VM at 150% and 200%, the recompose verifier at 150% (87 frames, 0 mismatches), and two displays at 100% and 200% with a window across both.
- Animations: deliberately not done. The design only says "fades and small translates, 120-180 ms"; the decision (2026-10-19) was to design window motion together with the dock and launcher in milestone 3.
Decision made without sign-off: the compositor draws every titlebar, including for our own apps (consistent look, and blur only works compositor-side). Revisit if you want apps to draw their own.
Open: verify on a real Linux Mint install, Fedora spec, real GPU testing.
